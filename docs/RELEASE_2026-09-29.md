# ShortlistProof - clarity release

This release redesigns the public website and private workspace without replacing
existing Supabase storage, row-level access controls or deployed payment functions.

## Delivered scope

- Server-rendered landing page with an independent Chevening preparation position,
  navy/ivory/gold design, responsive layouts and no fabricated customer testimonials.
- Local free check with transparent wording-cue limitations and downloadable
  reflection questions that do not include the user's draft.
- Six substantive preparation guides, a methodology page, a support form connected
  to the existing support function, and consistently styled privacy/terms pages.
- Public canonical metadata, JSON-LD, a sitemap and private/preview noindex rules.
- Redesigned workspace shell, real page/story search, mobile drawer, demo-safe links,
  improved sign-up/reset states, a resend-confirmation control and password visibility.
- Corrected literal progress text, fabricated story-evidence count and timing labels.
  Wording-cue matches are not presented as an admission score. Demo answers are now
  explicitly fictional evidence notes, not ready-to-submit generated essays.
- Keyboard interactions, focus styles, larger controls, unsaved-draft warnings,
  accessible story dialogs and a functional demo final-review checklist.

## Source architecture

`node scripts/build.cjs` applies asserted, small migrations to the existing portal
and appends `assets/portal-experience.js`, producing `portal-enhanced.js` for delivery.
This preserves the existing database contracts. An upstream anchor change fails
build rather than silently skipping a required fix. Do not manually edit the
generated file. Public pages use `lib/site.js` and `lib/guides.js`.

Run `node tests/release.cjs` for source, route, metadata and safety assertions.
Run `python tests/browser.py` after installing Playwright 1.57.0 and its Chromium
browser. CI publishes source and browser screenshots for review. Browser tests
explicitly distinguish mocked account/support responses from real integration tests.

## Remaining commercial launch gates

1. Identify the legal operator/merchant and finalise the applicable privacy,
   retention, processor, commercial, tax and refund information. The current
   pre-launch notices are not a completed jurisdiction-specific legal compliance review.
2. Complete live payment-provider onboarding, verify webhook entitlement/fulfilment
   and refund/revocation, then enable the existing fail-closed billing configuration.
   No live purchase or transfer is activated by this release.
3. Verify email delivery and a real signup -> confirmation -> sign-in -> recovery
   cycle. Confirm Supabase production Site URL and exact allowed redirects including
   `/login?confirmed=1` and `/login?recovery=1`. Enable suitable abuse protection and
   breached-password checks before expanding access. UI tests do not prove email delivery.
4. Test authenticated save/reload, private upload, deletion and cross-user isolation
   using dedicated non-personal QA accounts before a paid launch.
5. Azure Foundry remains disabled: a real subscription/project, verified credit
   eligibility, model deployment, secure server-side credentials, spending controls
   and approved data-processing configuration are required before activation.

## Verification limits

No SEO ranking, conversion uplift, scholarship outcome, WCAG certification or full
production-readiness claim is made by this release. Review the CI results and the
exact deployed commit. No live customer payment or private account operation is
performed by the regression suite.
